### 프로젝트의 구조 및 흐름

![로그인 아키텍쳐.png](attachment:82eccacd-ae52-48ce-98c0-e17c45a6e27d:로그인_아키텍쳐.png)

- **구조 개요**
    - **Unity**: 클라이언트 (게임 화면 및 사용자 인터페이스)
    - **Node.js**: 중간 API 서버 (Unity ↔ MySQL 중계)
    - **MySQL**: 데이터 저장소 (회원 정보 및 아이템 정보 관리)
- **Node.js 사용 목적 및 이유**
    - Unity와 MySQL 사이의 **데이터 중계 서버** 역할
    - RESTful API를 통해 클라이언트가 간결하고 안전하게 데이터 요청 가능
    - DB 연결, 사용자 인증, 요청 검증 등 **보안 및 비즈니스 로직을 서버에서 처리**함으로써 클라이언트 보안성 강화
- **MySQL 사용 목적 및 이유**
    - **회원 가입, 로그인 등 사용자 계정 정보** 관리
    - 게임 시작 시 기본으로 제공되는 **아이템 정보 저장 및 조회**
    - **SQL 기반의 데이터 생성/조회/수정/삭제(CRUD)가 편리**하고 직관적
        - 스크립트보다 테이블 기반 관리가 체계적이며 확장성이 우수함
    - **아이템 정보 추가/삭제/변경이 용이**하여 추후 콘텐츠 확장에 유리
    - 실무와 유사한 형태로 **DB 연동 경험을 학습**하기 위해 선택함
        - 간단한 JSON 파일로도 처리가 가능하지만, 실전 DB 설계를 경험해보고자 MySQL을 채택함

### 프로그램의 기술적 특징

- Unitask 사용
    - 캐릭터의 공격 시퀀스, 게임의 페이즈 진행 사용에 대하여 사용
        - 특정 시퀀스를 원하는 흐름에 맞춰서 제어 할수 있기에 사용
        - 코루틴보다 코드의 흐름을 직관적으로 작성 할 수 있기에 사용
- SciptableObject 사용
    - 데이터 베이스로 부터 받은 아이템 정보를 유니티 내에서 접근하기 위해 스크립터블 오브젝트 사용
        - 데이터 베이스에서 받은 정보를 잘 받았는지 에디터에서 확인 함으로써 디버깅에 용이하기에 사용
        - 데이터 베이스에 받은 데이터를 직관적으로 접근하는 것이 용이하기에 사용
- DoTween 사용
    - 보스 등장시 카메라 움직임을 구현 할 때 사용
        - 움직임과 관련된 애니메이션을 관련된 코드를 작성할때  DoTween 라이브러리를 통해 간결하게 작성할 수 있기 때문에 사용

### 회고 및 성장 포인트

- 아쉬운점
    - 게임 진행 중 몬스터 객체 중첩시 스프라이트 우선순위 처리에 어려움을 겪음
    - 체계적으로  프로그램을 설계하지 못한 아쉬움
- 성장한 점
    - 유튜브 교육 영상을 거의 참고 하지 않고 스스로의 힘으로 게임의 기능을 구현할수 있게 됨
    - 유사 코드 후 우선 작업 후 그에 따라 로직에 맞춰 작성하는 습관 형성
- 추가 예정인 기능및 수정 예정사항
    - 일반 필드 몬스터 처리 후, 재화를 드랍하는 시스템
    - 재화를 통한 플레이어 캐릭터 스탯 육성 시스템
    - Order in Layer를 설정하여 몬스터 스프라이트 우선 순위 정리 필요
